# 首轮页面效果图提示词

模式：Codex 内置 imagegen。用途：朋友的梗 Android App 页面视觉提案，不是已实现界面。

```text
Use case: ui-mockup
Create a polished high-fidelity Android app UI concept board for a Chinese private friendship memories app named exactly “朋友的梗”. Three complete portrait mobile screens side by side on a clean neutral presentation background. Flat straight-on UI, crisp readable Simplified Chinese, no physical phone hardware, no perspective distortion, no external brand logos. Large enough that text and controls are legible. Restrained friendly visual style, light neutral surfaces, comfortable spacing, clear typography and one subtle consistent accent. The feeling is a personal shared collection of inside jokes between friends, not romance or a public social network. Treat visual styling as a proposal, not an established brand system.

Show only the following confirmed MVP capabilities. Use illustrative names and content and a small board caption “视觉提案 · 示例内容”.

Screen 1 — space list. Header “朋友的梗”, section “我的空间”, button “创建空间”. Two understated friend space rows: “与小陈”, state “使用中”; “与阿林”, state “已冻结 · 只读”. The list should feel personal and calm. A compact profile/settings icon is acceptable; no community tab, followers, streaks, leaderboard, search or public feed.

Screen 2 — inside the active space. Header “与小陈”, small private-space label “仅双方可见”. A simple list of inside-joke cards with a short phrase as the visual focus and a restrained background excerpt: “我来早了”, excerpt “那次聚餐迟到后，他进门的第一句话。”; “下次一定”, excerpt “每次约早起，我们都会说这四个字。” One card can include a small illustrative café snapshot without identifiable people. Display the original author, for example “小陈记录”. Add one clear action “记一个梗”. No comments, reactions, automatic resurfacing or unsupported features.

Screen 3 — create entry. Header “记一个梗”, a clear primary “保存” action. Field label “这个梗” with sample value “我来早了”; a larger field “发生了什么” containing a short background. An attachment area labeled “添加图片”. Show the default rule as short supporting text “保存后仅你可编辑和删除”, without implying shared editing is enabled initially. The new entry UI should not promise real-time collaboration, voice support or immutable storage. Make it look feasible to implement using Jetpack Compose.

All three screens must share the same component language, spacing and typography. Prefer meaningful readable labels and short content over decorative dashboards. Do not add hearts, couple status, AI, analytics, badges, subscription, microphone recording, extra onboarding requirements or security promises that the platform cannot decrypt. Do not invent more product functionality to fill space.
```
