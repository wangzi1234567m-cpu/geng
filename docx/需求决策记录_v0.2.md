# 双人梗簿需求决策记录

版本 v0.2｜日期 2026年11月6日

本文记录产品负责人在 PRD v0.1 之后明确确认的新增决定。本记录与《双人梗簿_PRD_v0.1.docx》及架构稿共同使用；发生冲突时，以本文的最新已确认决定为准。既有 Word 文档尚未同步修订，不应单独作为最新开发基线。建议与待确认项不作为已确认需求。

## 1 已确认的产品决定

| 主题 | 已确认规则 |
| --- | --- |
| 账号 | 邮箱和密码登录；注册时验证邮箱 |
| 邀请入口 | 创建空间后，可输入朋友的邮箱或用户 ID 发起邀请；首版支持两种方式 |
| 加入确认 | 被邀请的朋友确认后才加入；邮箱和用户 ID 是邀请对象的身份标识，不是直接进入空间的凭据 |
| 核心记录 | 每条主要记录一个双方理解的梗，可以是几个文字；旁边可补充事情背景或细节，并可附加图片 |
| 记录目的 | 保存朋友共同经历、被反复引用的话语和会心一笑的回忆；不将其定义为公开内容社区 |
| 编辑体验 | 首版手动保存，不做实时协同；并发修改提示冲突，避免静默覆盖 |
| 删除 | 永久删除，不提供回收站恢复 |
| 注销归属 | 按记录最初创建者判断，而非最后编辑者 |
| 注销删除 | 清除注销账号创建的整个梗及其附图，另一方参与编辑过也一样；即使空间冻结也要清除 |
| 注销保留 | 另一方创建的梗保留，注销者参与编辑过也不改变其归属 |
| 注销与空间 | 注销时同时冻结该账号所在的活动空间；另一方创建的内容保留并可只读查看 |
| 邀请对象范围 | 首版仅邀请已注册且已验证邮箱的用户，不支持未注册邮箱认领邀请 |
| 规则优先级 | 注销删除优先于冻结历史保留；冻结不代表内容永远不会因注销而减少 |
| 隐私模式 | 首版服务端受控解密；云端应用可处理内容，客服与运营默认不可查看；不承诺服务器失陷后内容仍不可读取 |
| 部署 | 中国大陆地区，使用 Docker 部署，先小范围试用 |

## 2 保持不变的已确认规则

Android 独立 App，首版文字和图片；每空间两人，一个账号可以与不同朋友分别拥有空间。每条默认仅原作者可编辑和删除；由原作者开启或关闭共同编辑，开启时双方均可编辑和删除，另一方不能切换权限。

任一方退出空间时整个空间冻结，双方均可查看退出时的只读历史。普通操作不能再新增、编辑、删除或切换权限；本次明确的账号注销清除为例外。语音和群体空间为后续扩展，不进入本次已确认 MVP。

## 3 对主体架构的修订

### 3.1 内容语义

记录核心是一个梗，内容设计需表达简短梗文字、背景细节和附图。字段必填性、是否设置独立梗标题、文字长度及图片数量尚未确认；本记录不决定表结构和接口。

### 3.2 身份与会话

身份模块需覆盖邮箱密码登录和注册邮箱验证。邮箱投递、密码找回、验证邮件重发、验证码或链接的过期与防滥用策略需要在后续详细设计中明确。不得将未验证邮箱的注册行为当作已证明邮箱归属。

空间模块支持邮箱和用户 ID 两种邀请对象识别方式，最终加入仍须被邀请者确认，并遵守一个空间两位成员的上限。不能因为请求知道对方邮箱、用户 ID 或空间标识，就授予读取权限。用户 ID 不应包含邮箱等直接身份资料，具体生成和展示方案后续设计。

邀请待处理期间不授予回忆访问权；被邀请者身份核对、邀请状态及并发接受的行为在详细设计中明确。未注册邮箱是否可接收邀请、用户 ID 是否可用于精确查找以及相应防枚举措施尚待细化。

### 3.3 核心删除与冻结规则

领域规则需要区分普通内容操作、退出冻结和账号注销清除。不能再把“冻结后任何路径都不可删除”作为全局绝对规则；应改为普通业务只读，经过授权的注销清除流程可以删除原作者内容。

注销清除属于受控用例，不是允许后台脚本任意绕过权限。其身份确认、处理结果、失败重试和清除范围需可验证；数据库、原图及派生资源、本地或服务端缓存、备份保留策略都需要纳入后续删除设计。

不能销毁整个双人空间的共享密钥来清除某一位成员的内容，否则会使另一方应保留的记录不可读取。密钥粒度和删除实现需在存储设计阶段据此评审。

### 3.4 服务端受控解密

核心服务和受限媒体处理组件可按用途获得解密能力，运营客服没有默认查看入口与权限。内容、密钥、备份和生产发布权限仍需分开管理，日志及第三方统计不采集正文、图片、密码或凭据。

本次不采用“只有双方设备能解密”的端到端加密架构。未来若升级需要单独设计迁移、密钥及设备恢复，不能视为切换一个配置即可完成。

### 3.5 部署与运维

Docker 是部署方式，不代替分层、空间隔离或高可用设计。核心应用、受限后台任务和基础设施按现有模块化方案设计；对外入口、私网访问、持久化、密钥注入、日志、备份及升级回滚在部署详细设计阶段明确。

中国大陆地区为部署范围，不在缺少预算和运维能力信息时指定云厂商、机器数量或冗余级别。是否对公众开放及相关上线条件另行核实，不能以“小范围试用”自动推断任何豁免。

## 4 新增验收关注点

- 邮箱所有权验证与登录流程符合最终确认的身份方案；不将密码或有效验证凭据输出到日志。
- 邮箱或用户 ID 均可发起邀请；对方未确认时不能成为空间成员或读取回忆；第三个账号不能通过邀请加入已满双人空间。
- 两人同时编辑同一梗时不静默覆盖；发生冲突后能够获知保存未成功，不丢失用户尚未提交的输入。
- 普通删除执行永久删除产品语义，不提供回收站恢复；底层清除范围与完成时点按最终删除方案验收。
- 注销 A 时，A 最初创建的梗及其附图被清除，包括 B 参与编辑过的记录以及冻结空间中的记录。
- 注销 A 时，B 最初创建的记录保留，即使 A 编辑过；B 保留内容所需的图片和解密能力不被误清除。
- 客服运营默认无法查看回忆正文和图片；服务端受控解密不被错误宣传为端到端加密。
- 容器重建和应用升级不造成持久化内容及必要解密能力丢失，具体恢复目标另行确定。

## 5 仍待确认或细化

1. 邀请过期撤销、拒绝与误加入处理，以及朋友加入前是否可先记录；邮箱和用户 ID 两种邀请入口、对方确认加入、仅邀请已注册且验证邮箱用户均已确定。
2. 注销时冻结相关活动空间已确认；待加入空间及其尚未完成邀请的关闭细节仍需在状态机设计中明确。
3. 注销后的身份展示，以及账号再次注册是否视为新身份。
4. 永久删除的在线不可访问时点、资源物理清除时限、备份过期清理及恢复后防止已删除内容重新出现的措施。永久删除不提供产品恢复，不等于声称各副本与备份瞬间完成物理擦除。
5. 邮箱提供方、密码找回体验、媒体格式与大小、多图规则、纯图片记录、字段必填性及排序方式。
6. 小范围试用的参与人数、预算、开发技术栈、可靠性目标和设备兼容范围。

本次只记录并修订已确认决定，不直接开始编码、选定云资源或扩大 MVP 功能范围。
