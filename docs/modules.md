# 基础模块与扩展边界

第一阶段保留五个 Maven 编译模块与一个后端进程。业务模块用包组织，避免首版拆成多个微服务；Android 暂保留一个 app 编译模块，业务页面随纵向功能交付。

| 业务边界 | 当前实际内容 | 后续进入条件 |
| --- | --- | --- |
| identity 账号身份 | AccountState、SessionAuthenticator 端口、主体基础表与自读策略 | 邮箱密码与验证、会话、限流、真实邮件及凭据加密通过阶段 2 |
| space 双人空间 | SpaceState、空间和成员表、双人硬约束、成员可见性函数 | 邀请与冻结用例、同事务锁顺序通过阶段 3 |
| entry 梗记录 | 权限策略、版本校验、授权协调、JDBC 权限元数据读取、密文列基础表 | 正文加密、授权写入、冲突与永久删除链路完整后开放业务 API |
| media 私密媒体 | MediaKind、PrivateMediaReader 端口、独立 schema | 真实存储、加密、授权流式读取和资源生命周期验证后接入；端口目前无实现 |
| lifecycle 清理与冻结 | 专属应用包边界、ops schema 对应用账号不可见 | 按最初作者清除、注销优先、保留他人内容、受控清理任务验收后接入 |
| transaction 事务 | ActorTransactions、Spring JDBC 实现、真实连接池隔离验证 | 首个业务用例须从已验证会话取得 actor；不接受客户端指定数据库身份 |

没有实现的模块不注册假成功 Bean，不开放占位 CRUD 或管理接口。应用端口位于 application，第三方 SDK 与 SQL 位于 infrastructure，由 bootstrap 装配。API 层不直接访问存储。

## 读写与隐私边界

- 读事务设置 JDBC readOnly；写事务独立声明。两者均在同一连接中设置事务局部 actor，提交和回滚均清除；禁止嵌套边界替换身份或升级只读事务。
- RLS 依赖已认证应用传入的 actor，属于纵深防护，不是数据库凭据泄露或应用失陷后的隔离承诺。geng_app 不能管理角色、建表、修改策略、绕过 RLS 或访问 ops。
- 成员判断函数是迁移账号拥有的窄范围 SECURITY DEFINER 只读函数，固定 search_path，PUBLIC 无执行权限。成员表不 FORCE RLS，供函数所有者完成判断；业务应用不是表所有者，也不是迁移账号成员。
- 当前业务表仅授予 SELECT，未授权任何产品写入口。写事务能力经过专用测试表验证，不能据此声称梗编辑或冻结并发已验收。
- 字段分类采用规范化表、索引和外键；梗正文预留为经过认证加密的密文载荷，不是将整条记录塞进 JSON。加密实现、KMS 与密钥轮换仍属于后续功能阶段。
- 媒体种类首版仅 IMAGE。未来语音新增处理适配、容量与格式校验、客户端入口和迁移，复用已有授权及生命周期边界，不通过开放公共对象地址实现。

账号、媒体与清理功能仅建立边界，当前不存在可对真实用户试用的业务闭环。
